# Logria 1.4.2 (Android build 16)

## 简体中文

- 本轮进度边框高亮今日已记录的训练／休息／跳过项，不再圈下一天；完成最后一天后，当天保留刚结束轮次的进度，撤回／取消撤回同步更新。
- 训练编辑页可拖动动作手柄排序，草稿恢复及保存历史保留顺序和输入。计划页提供独立排序面板，拖动后保存模板顺序，关闭则不改动。
- 日历与今日复用原生营养表格，逐食材展示，不再直接显示 Markdown 源码；复制仍为 Markdown 表格。
- 空动作模板的当日训练完成时，可选保存为本日模板、仅保存记录或取消继续编辑。已有模板不覆盖，记录与模板写入同一事务。
- 单动作新增「按照上次内容」，按所选日期寻找更早的同动作／同备注变式，跨计划和轮次回填组数、重量、次数。替换已有输入前确认，不带入旧 RIR／感受，保留文本重量零／null 规则及首组一次性同步。
- 双语内嵌手册、更新日志和测试说明同步更新；152 项自动测试通过。

下载 `logria-v1.4.2-android.apk` 覆盖安装，包括本地 build 15；不要先卸载或清除数据。
数据库 schema 7、完整备份格式 1 和签名不变，无新增权限。模板仅保存动作顺序、组数、次数范围及首组数值参考重量，文本重量、RIR 和感受仍留在历史中。
旧 Release／标签／附件保留。完整备份未加密，请妥善保管。沿用开发签名以保持升级兼容，非 Google Play 发布包。

## English

- Round progress outlines today's recorded training/rest/skip slot, not the next
  pending slot. The just-finished round stays visible that journal day, including undo/redo.
- Drag handles reorder workout drafts/edits while retaining input and saved order.
  Day-plan templates have a separate sorting panel: drag and Save, or dismiss without changes.
- Calendar and Today share native per-ingredient nutrition tables; Markdown remains
  the clipboard format instead of visible source markup.
- Finishing a new current workout on a template-free day offers save-as-day-template,
  log-only or cancel. No existing template is overwritten; both writes are atomic.
- Per-exercise history fill uses the latest earlier journal-day record of the exact
  exercise/variant across plans/rounds. It confirms replacement of nonempty input,
  copies set count/loads/reps but not RIR/feelings, preserves text-load zero/null
  behavior and re-enables first-set one-shot filling.
- Updated bilingual bundled guides/changelog and testing docs; 152 tests pass.

Install `logria-v1.4.2-android.apk` over the existing app, including local build 15.
Do not uninstall or clear storage. Database schema 7, full backup format 1 and
signing identity are unchanged, with no new permissions. Templates store exercise
order, set count, rep range and first numeric reference weight, not text loads/RIR/feelings.
Older releases, tags and assets remain intact. Backups are unencrypted sensitive
files. The existing development signature is retained for upgrade compatibility,
not Google Play distribution.
